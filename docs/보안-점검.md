# 하늘향 보안 점검 & RLS 설정 가이드

> 이 사이트는 **정적 HTML + Supabase(anon 공개키)** 구조입니다.
> anon 키는 브라우저에 그대로 노출되는 게 정상이며(누구나 볼 수 있음),
> **실제 보안은 Supabase의 RLS(Row Level Security) 정책이 100% 담당**합니다.
> 프론트엔드 코드(로그인 화면, `checkAuth`)는 UX일 뿐, 보안 장치가 아닙니다.

---

## 1. 이번 코드 변경으로 처리한 것

| 항목 | 내용 |
|---|---|
| 관리자 승인 검사 | `dashboard.html` / `editor.html` 진입 시에도 `profiles.is_approved` 를 확인하도록 추가 (기존엔 로그인 화면에만 있었음). 미승인 계정은 강제 로그아웃 |
| 저장형 XSS 방어 | 게시글 제목·본문·이미지 URL을 화면에 넣기 전 이스케이프 (`assets/app.js`의 `HY.esc`, 에디터의 `escAttr`) |
| 이미지 출처 제한 | 상세/목록 페이지가 신뢰 도메인(Supabase, 자사 도메인) 이미지만 렌더 (`HY.safeImg`) |
| 관리자 페이지 색인 차단 | `admin/*.html` 에 `noindex`, `robots.txt` 에 `Disallow: /admin/` |

## 2. Supabase 쪽에서 **직접 확인/설정**해야 하는 것 (필수)

프론트 코드로는 막을 수 없습니다. Supabase 대시보드 → **SQL Editor** 에서 아래를 실행하세요.

### 2-1. 현재 상태 자가 점검

SQL Editor에서 실행해 결과를 확인합니다.

```sql
-- RLS 켜져 있는지
select relname, relrowsecurity
from pg_class
where relname in ('posts', 'profiles');

-- 현재 정책 목록
select schemaname, tablename, policyname, cmd, roles, qual, with_check
from pg_policies
where tablename in ('posts', 'profiles')
order by tablename, cmd;
```

`relrowsecurity` 가 `posts`, `profiles` 모두 `true` 여야 하고,
아래 3번 같은 정책이 있어야 합니다. 없다면 3번을 실행하세요.

### 2-2. 브라우저에서 빠르게 확인 (개발자도구 콘솔)

로그아웃 상태로 사이트를 연 뒤 콘솔에 붙여넣기:

```js
// 비로그인 상태에서 글 작성이 되면 => 취약 (RLS 필요)
const { data, error } = await window.supabase
  .createClient(
    "https://eyoahkbqfxcisvmkvikp.supabase.co",
    "여기에_anon_key"
  )
  .from('posts').insert({ title: '__probe__', status: 'draft' }).select();
console.log({ data, error });
// 기대값: error.code === '42501' (row-level security 위반)
// data 에 값이 들어오면 => 지금 누구나 글을 쓸 수 있는 상태입니다. 3번 즉시 실행.
```

### 2-3. 권장 RLS 정책

```sql
-- ========== posts ==========
alter table public.posts enable row level security;

-- (읽기) 발행된 글은 누구나
drop policy if exists "posts_public_read_published" on public.posts;
create policy "posts_public_read_published"
on public.posts for select
to anon, authenticated
using (status = 'published');

-- (읽기) 승인된 관리자는 모든 글
drop policy if exists "posts_admin_read_all" on public.posts;
create policy "posts_admin_read_all"
on public.posts for select
to authenticated
using (
  exists (
    select 1 from public.profiles p
    where p.id = auth.uid() and p.is_approved = true
  )
);

-- (쓰기/수정/삭제) 승인된 관리자만
drop policy if exists "posts_admin_write" on public.posts;
create policy "posts_admin_write"
on public.posts for all
to authenticated
using (
  exists (select 1 from public.profiles p where p.id = auth.uid() and p.is_approved = true)
)
with check (
  exists (select 1 from public.profiles p where p.id = auth.uid() and p.is_approved = true)
);

-- ========== profiles ==========
alter table public.profiles enable row level security;

-- 본인 프로필만 조회
drop policy if exists "profiles_self_read" on public.profiles;
create policy "profiles_self_read"
on public.profiles for select
to authenticated
using (id = auth.uid());

-- 최고 관리자는 전체 조회 (계정 승인 관리 화면용)
drop policy if exists "profiles_superadmin_read" on public.profiles;
create policy "profiles_superadmin_read"
on public.profiles for select
to authenticated
using (
  (select email from auth.users where id = auth.uid()) = 'eowert72@gmail.com'
);

-- is_approved 변경은 최고 관리자만. (본인 self-approve 차단)
drop policy if exists "profiles_superadmin_update" on public.profiles;
create policy "profiles_superadmin_update"
on public.profiles for update
to authenticated
using (
  (select email from auth.users where id = auth.uid()) = 'eowert72@gmail.com'
)
with check (
  (select email from auth.users where id = auth.uid()) = 'eowert72@gmail.com'
);
```

> 가입 시 `profiles` 행이 자동 생성되도록 트리거(`on auth.users` → `insert into profiles`)가
> 이미 있다는 전제입니다. 없다면 회원가입 후 행이 안 생겨 로그인 검사에서 막힙니다.

### 2-4. Storage(이미지 업로드) 정책

`images` 버킷:

```sql
-- 읽기: 공개
create policy "images_public_read"
on storage.objects for select
to anon, authenticated
using (bucket_id = 'images');

-- 업로드/수정/삭제: 승인된 관리자만
create policy "images_admin_write"
on storage.objects for insert
to authenticated
with check (
  bucket_id = 'images'
  and exists (select 1 from public.profiles p where p.id = auth.uid() and p.is_approved = true)
);
```
